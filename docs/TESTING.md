# Проверки StickyDesk

Текущая версия приложения — 0.3.1. Общий запуск:

```powershell
.\scripts\test.ps1
# При наличии локального кэша:
.\scripts\test.ps1 -Offline
```

## Автоматические проверки

`StickyDesk.Core.Tests` содержит 23 проверки:

- UTF-8, кириллица, BOM и CRLF;
- обнаружение внешней записи и удаления связанного файла;
- явное восстановление удалённого файла, сохранность Unicode/BOM/CRLF и отказ от перезаписи появившегося файла;
- переименование без изменения байтов, смена регистра, совпадения имён, недопустимые и зарезервированные имена Windows, переименование отсутствующего файла;
- резервные копии, повреждённая конфигурация, неверная кодировка и защита соседних файлов;
- вложенное оформление, код, чек-листы и нумерация;
- ссылки, положение курсора в исходнике, экранирование, HTML и незавершённая разметка.

`StickyDesk.UIHarness --self-test` содержит 70 проверок нативных контролов и файловой сессии:

- крупное название внутри заметки, линия под ним и положение основного текста;
- шрифты, стили, Unicode, чекбоксы и ссылки в RichEdit;
- сохранность байтов Markdown при переключении режимов;
- запись исходника вместо RTF и обновление предпросмотра;
- независимость названия от первой строки, переименование, отмена и восстановление из конфигурации;
- обнаружение удаления через FileSystemWatcher, сохранение текста стикера, запрет автоматического создания файла;
- явное восстановление, повторное удаление, перезапуск с копией восстановления и очистка текста отсутствующей заметки;
- защита пустой копии восстановления при возврате другого файла;
- сохранение изменений при возврате и повторном подключении файла, снятие конфликта при совпадении текста и возобновление автосохранения;
- удаление с копией текущего текста, отмена и сбой удаления, сохранность соседнего файла, работа с отсутствующим файлом и пустая сессия после перезапуска;
- синхронное изменение заголовка и имени файла, отмена, сохранение нового пути, автосохранение и FileSystemWatcher после переименования, совпадения имён и внешние файлы.

Для 0.2.5 проверен реальный перенос специально созданного тестового файла через Windows в Корзину. Используется [`FileSystem.DeleteFile` с `SendToRecycleBin`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.fileio.filesystem.deletefile?view=net-10.0). Пользовательские заметки в проверке не удаляются.

Каждый запуск использует отдельный каталог `.local/test-runs`. Эти консольные проверки запускаются через скрипт, а не через `dotnet test`.

Для 0.3.0 прошли все 82 проверки приложения и ещё 11 проверок установщика через `scripts/test-installer.ps1`: установка, запуск виджета, защита работающей программы, обновление, удаление и сохранность данных. Оформление карточки проверено в отдельном тестовом окне.

Для 0.3.1 прошли 93 проверки приложения. Новые сценарии проверяют реальный регион HWND до первого изменения размера и после переприкрепления, закрытие через меню и оконную команду, сохранение текста и настроек, перезапуск, повторное открытие, удалённый файл и отказ записи копии восстановления. Нативная диагностика также проверяет скругление четырёх углов.

## Ручная приёмка

- Подтверждено пользователем отображение стикеров на рабочем столе после исправления композиции.
- В отдельном тестовом окне проверялись ввод, автосохранение, внешнее изменение файла, просмотр Markdown, переключение режимов и редактирование названия.
- Для 0.2.3 в тестовом окне удалён Markdown-файл, открыто меню красного статуса и выполнено «Восстановить файл»: текст сохранён, файл создан, статус сменился на «Файл восстановлен».
- Диагностикой проверены WS_CHILD, WS_EX_TOOLWINDOW, layered-режим и отсутствие TopMost.

Ещё требуется проверить перезапуск Explorer, 100/125/150% DPI, отключение монитора, автозапуск после входа в Windows, полноэкранные приложения, все ветки диалога конфликтов, заполненный диск и длительную работу.
